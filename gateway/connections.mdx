A **Connection** is a link from Factory Flow Gateway to one machine, control system, message broker, web API, or database. Each connection uses one **protocol**, which is the "language" that machine or system speaks.

You don't need to know these protocols in depth to set one up. You need the connection details (address, port, credentials) for your equipment, which your machine builder, integrator, or plant IT team can usually provide. The sections below explain what each protocol is in plain terms and which fields you fill in.

## Supported Protocols

When you add a connection, protocols are grouped into four kinds. You can filter by kind or search by name. Each kind has its own page with the fields to fill in:

| Kind | Protocol | What it is |
|------|----------|------------|
| [**Industrial**](/gateway/connections/industrial) | **OPC-UA** | A modern, secure standard for exchanging real-time industrial data between machines, PLCs, and software such as Kepware or Ignition. |
| | **Siemens S7** | Siemens' own protocol (S7comm) for reading S7-300, S7-400, S7-1200, and S7-1500 PLCs directly. |
| | **Modbus** | One of the oldest and most widely supported industrial protocols, used to read data directly from a device's memory registers. |
| | **EtherNet/IP** | An industrial networking protocol (built on CIP, the Common Industrial Protocol) used by Rockwell Automation / Allen-Bradley PLCs. |
| | **MTConnect** | An open data standard for manufacturing equipment, where a machine (or an "agent" in front of it) publishes standardized production data. |
| | **FOCAS** | Fanuc's protocol (Fanuc Open CNC API Specification) for reading data directly from Fanuc CNC controllers. |
| [**Streaming**](/gateway/connections/streaming) | **MQTT** | A lightweight messaging protocol where devices publish data to a central "broker" and other systems subscribe to receive it. |
| | **WebSocket** | A persistent connection over which a server streams messages to the gateway as they happen. |
| [**Web APIs**](/gateway/connections/web-apis) | **HTTP** | The protocol the web runs on. Used here to poll a REST API, or to receive data pushed to the gateway as a webhook. |
| | **GraphQL** | A query-based API standard, used here to poll a GraphQL endpoint for exactly the fields you request. |
| [**Databases**](/gateway/connections/databases) | **Microsoft SQL Server** | MES, historian (for example AVEVA or FactoryTalk), and OEE databases. |
| | **PostgreSQL** | PostgreSQL and TimescaleDB databases. |
| | **MySQL / MariaDB** | MySQL and MariaDB databases. |
| | **InfluxDB** | Time-series data from InfluxDB 1.x, 2.x, and 3. |

<Note>
  New **FOCAS** connections are temporarily unavailable and show as **Coming soon** in the protocol picker. Existing FOCAS connections can still be opened and edited.
</Note>

## Managing Connections

<Steps>
  <Step title="Add a connection">
    From the connections list, click **Add Connection**. You can:

    - **Add manually**: pick a protocol from the protocol picker, which shows every protocol with its logo, grouped by kind (Industrial, Streaming, Web APIs, Databases) and searchable. Then fill in its fields as described on the protocol pages.
    - **Scan Network**: let Factory Flow Gateway find devices on your network, then add connections straight from what it finds. See [Scan Network](/gateway/connections/scan-network).

    <Frame>
      <img className="block dark:hidden" src="/images/gateway/connection-new-form.png" alt="New connection form with protocol type selector and protocol-specific fields" />
      <img className="hidden dark:block" src="/images/gateway/connection-new-form-dark.png" onError={(e) => { e.currentTarget.src = "/images/gateway/connection-new-form.png"; }} alt="New connection form with protocol type selector and protocol-specific fields" />
    </Frame>
  </Step>
  <Step title="Save">
    The form checks your settings before saving, so problems such as an out-of-range port, a missing host, or a URL with the wrong scheme are caught right away instead of showing up later as a connection error. A few other rules apply:

    - Connection names must be unique.
    - Only one connection per server. If a connection to the same server already exists, add endpoints, streams, or queries to it instead of creating a second one.
    - Only one HTTP connection can be in webhook mode.
  </Step>
  <Step title="Test the connection">
    Use **Test Connection** to confirm the gateway can reach and sign in to the target. Testing uses the saved settings, so save your changes first.
  </Step>
  <Step title="Explore available data">
    Once connected, use the **Explore** browser to see the topics, registers, nodes, or tags the connection can reach and read live values, which helps you find the exact address to map in [Machines](/gateway/machines).

    For connections built on documents or queries (HTTP, GraphQL, WebSocket, SQL databases, and InfluxDB), Explore shows the whole response, message, or first row so you can pick a field from it. For saved queries, you can also edit a query in place and save the change back to the connection, or save it as a new query. The panel tells you how many data points use a query, since every data point that reads from it is affected by a change.

    <Frame>
      <img className="block dark:hidden" src="/images/gateway/connection-explore.png" alt="Explore browser showing available topics, registers, or nodes for a connection" />
      <img className="hidden dark:block" src="/images/gateway/connection-explore-dark.png" onError={(e) => { e.currentTarget.src = "/images/gateway/connection-explore.png"; }} alt="Explore browser showing available topics, registers, or nodes for a connection" />
    </Frame>
  </Step>
  <Step title="Edit, enable/disable, or delete">
    Open any connection to edit its settings, view its logs, or see which machines use it. Each connection can be enabled or disabled without deleting it, or removed entirely.
  </Step>
</Steps>

<Tip>
  Use **Filters** on the connections list to narrow it by **Status** or **Protocol**. Each option shows how many connections it matches.
</Tip>

## Security

Every protocol that supports TLS lets you supply your own CA certificate, client certificate, and client key for that connection, and choose whether to **Verify server certificate** (recommended). A few protocol-specific notes:

- **Modbus**: TLS only applies in **TCP** mode; RTU (serial) connections don't support it.
- **OPC-UA**: security is set through **Security mode** and **Security policy**, plus a client certificate and private key when signing or encryption is required.
- **MQTT, MTConnect, HTTP, GraphQL, WebSocket, SQL databases, InfluxDB**: a TLS toggle (or an `https://` / `wss://` URL) with certificate options.

Each connection shows a lock icon next to its address so you can see at a glance whether the link between the gateway and the device is encrypted.
