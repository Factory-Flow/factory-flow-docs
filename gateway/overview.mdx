**Factory Flow Gateway** is a desktop application you install on a PC located on your plant network. It connects directly to your machines, PLCs, and sensors using industrial communication protocols, collects the production data they expose, and securely forwards it to your Factory Flow cloud (or self-hosted) organization.

Use Factory Flow Gateway when your machines can't send data to Factory Flow on their own — for example, older equipment that only speaks Modbus, a Siemens PLC on S7, or production data that already sits in an MES or historian database. The gateway sits between that equipment and Factory Flow, translating whatever protocol your machine speaks into data points that show up on your dashboards.

## Why Factory Flow Gateway?

For a handful of machines, wiring up connections by hand — writing scripts, or building flows in a general-purpose tool like Node-RED — works fine. That approach stops scaling once you're managing data across dozens or hundreds of machines: every protocol needs its own custom logic, every mapping is hand-wired, and the result is usually something only the person who built it can maintain.

Factory Flow Gateway is built for that scale. It handles the protocol-specific communication for you across every [supported connection type](/gateway/connections), and gives you the same guided, point-and-click way to [map raw values to your machines' data points](/gateway/machines) no matter which protocol is underneath. That means adding and mapping a new machine doesn't require someone who can write and maintain custom integration code — plant and IT staff can do it directly from the app.

## Supported Platforms

Factory Flow Gateway ships as a 64-bit desktop application for all three major operating systems:

| Platform | Installer format | Architecture |
|----------|-------------------|--------------|
| **Windows** | NSIS installer (`.exe`) | x64 |
| **macOS** | Disk image (`.dmg`) | Apple Silicon (arm64) and Intel (x64), as separate installers |
| **Linux** | AppImage | x64 |

<Tip>
  On macOS, download the installer that matches your Mac: the **arm64** one for Apple Silicon (M-series) Macs, or the standard one for Intel Macs. To check, open the Apple menu → **About This Mac** and look at **Chip** (Apple M…) or **Processor** (Intel).
</Tip>

## Installing the Gateway

<AccordionGroup>
  <Accordion title="Windows">
    Run the downloaded `.exe` file and follow the NSIS installer wizard. Once installation completes, launch **Factory Flow Gateway** from the Start menu.
  </Accordion>
  <Accordion title="macOS">
    Open the downloaded `.dmg` file and drag **Factory Flow Gateway** into your **Applications** folder. Launch it from Applications or Launchpad.
  </Accordion>
  <Accordion title="Linux">
    Make the downloaded AppImage executable and run it directly:

    ```bash
    chmod +x FactoryFlowGateway-x86_64.AppImage
    ./FactoryFlowGateway-x86_64.AppImage
    ```
  </Accordion>
</AccordionGroup>

<Note>
  Installers are distributed through your Factory Flow organization. If you don't have a download link, ask your Factory Flow admin, or check **Manage → Organization → Gateways** in the Factory Flow web app.
</Note>

## Can't Open the App?

Factory Flow Gateway isn't notarized/signed through every OS vendor's store program, so each operating system shows a warning the first time you open it. This is expected — here's how to get past it on each platform.

<AccordionGroup>
  <Accordion title="macOS: “can't be opened because Apple cannot check it for malicious software”">
    This is macOS **Gatekeeper** quarantining a downloaded app that isn't notarized. Two ways to get past it:

    **Option 1 — Right-click to open (easiest)**

    1. In **Applications**, right-click (or Control-click) **Factory Flow Gateway** and choose **Open**.
    2. Click **Open** again in the dialog that appears.
    3. You only need to do this once — after the first confirmed launch, macOS lets it open normally (including double-click).

    **Option 2 — Clear the quarantine flag from Terminal**

    If the right-click option doesn't work, or you're deploying to multiple machines, remove the quarantine attribute directly:

    ```bash
    xattr -cr "/Applications/Factory Flow Gateway.app"
    ```

    Then launch the app from **Applications** or **Launchpad** as usual.
  </Accordion>
  <Accordion title="Windows: “Windows protected your PC” (SmartScreen)">
    1. In the SmartScreen dialog, click **More info**.
    2. Click **Run anyway**.

    This only appears on the first run of a newly downloaded installer.
  </Accordion>
  <Accordion title="Linux: AppImage won't launch / “Permission denied”">
    Make sure the AppImage is executable before running it:

    ```bash
    chmod +x FactoryFlowGateway-x86_64.AppImage
    ./FactoryFlowGateway-x86_64.AppImage
    ```

    If it still won't launch, confirm `libfuse2` (or `fuse`) is installed — most distros require it to run AppImages:

    ```bash
    sudo apt install libfuse2
    ```
  </Accordion>
</AccordionGroup>

## First Launch

The first time you open Factory Flow Gateway, a **Welcome** window walks you through setup in three steps:

1. **System check**: checks this computer against the recommended CPU, RAM, and disk space for running the gateway. If something falls short, it shows which resource, and you can still choose **Continue anyway**.
2. **Connect to Factory Flow**: links the gateway to your organization with a gateway token. See [Registration](/gateway/registration).
3. **Done**: next, add a connection for each machine and map its data points.

If you're not ready, choose **Set up later**. The Welcome window appears again at the next launch until the gateway is connected, and you can always connect from **Settings → Server**.

<Tip>
  You can re-run the system check at any time from **Settings → Application → System Requirements**. See [Settings](/gateway/settings/application#system-requirements).
</Tip>
