Once you have one or more working [connections](/gateway/connections), the next step is telling Factory Flow Gateway which piece of data from which connection corresponds to which value on which machine.

This mapping step is the same guided, point-and-click process regardless of which protocol a machine's connection uses — which is what lets you scale from a handful of machines to hundreds without needing someone who can write custom integration code for each one.

## Machines Come From the Web App

Machines are created and managed in the Factory Flow web app, not in the gateway app itself. Once a machine is assigned to your gateway (in **Manage → Organization → Gateways**, or from the machine's own Data Source settings), it automatically appears in Factory Flow Gateway — there's no separate step to create it locally.

Each machine carries a **schema**: the list of data points Factory Flow expects from it (for example, part counts or spindle speed), each with a defined type: integer, float, boolean, or string. Each data point is also treated as a **counter** (only goes up, like a part count), a **measurement** (goes up and down, like a temperature), or a **state** (a label or flag, like RUNNING or door open), which decides which [checks](/gateway/machines/checks) are offered for it.

<Note>
  If a machine you expect to see isn't listed in the gateway, confirm it has been assigned to this specific gateway in the Factory Flow web app.
</Note>

## Machine Health

Each machine shows a health status so you can see at a glance which ones need attention. You can filter the machines list by it.

| Status | Meaning |
|--------|---------|
| **Live** | Every required data point is mapped and every connection feeding it is connected. |
| **Not connected** | Mappings are set up, but a connection feeding them is connecting or disconnected. |
| **Incomplete** | Some required data points from the machine's schema aren't mapped yet. |
| **Invalid data** | Values are being read, but some are being dropped instead of sent, for example because they're the wrong type or failed a check. |
| **Error** | A connection feeding this machine is in an error state, or a mapping points at a connection that was deleted. |
| **Not configured** | The machine has no enabled mappings yet. |
| **Disabled** | Collection for this machine is turned off on this gateway. |

## The Flow View

Open a machine to see its mappings as a diagram: the connections that feed it on the left, the machine's data points on the right (grouped by category, such as Production), and a line for each mapping between them. Lines are colored by the connection's live status and dashed when a mapping is switched off. Each data point card shows its latest value, and a warning if that value can't be sent.

Connections that this machine doesn't use yet are listed in a collapsible section under the diagram, so you can drag from them too.

- **Map by dragging.** Drag from a connection's right-edge handle onto a data point (or from a data point's left-edge handle onto a connection). The mapping editor opens with that connection already chosen, so you only need to pick the address.
- **Copy a setup by dragging.** Drag a mapped data point's card onto another data point to copy its whole setup there (source, conversions, and checks). You're asked to confirm first.
- **Remove a mapping.** Click a line to select it, then click **Remove** or press **Delete**.
- **Edit a mapping.** Click a data point card to open the [mapping editor](/gateway/machines/mapping).

## Part Count Sanity Check

When Part Count Good, Part Count Bad, and Part Count Total are all mapped and reporting, the gateway checks that Good + Bad equals Total. If they don't add up, a **Part counts don't add up** warning appears on the machine, since this usually means one of them is mapped to the wrong address or field.

## Enabling and Disabling

Both individual mappings and entire machines can be enabled or disabled independently. Disabling a mapping stops that data point from being collected without affecting the rest of the machine; disabling a machine stops all collection for it.

<Note>
  Data is only sent to Factory Flow while the collector is running. See [Dashboard](/gateway/dashboard).
</Note>
