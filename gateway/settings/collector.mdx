Controls how the collector gathers and forwards data, and manages its local send queue. See [Data Flow](/gateway/data-flow) for how these settings fit together.

## Behavior

| Setting | Default | Description |
|---------|---------|-------------|
| **Auto-start collector on app launch** | Off | Starts the collector automatically when the app opens. Takes effect the next time the app starts or restarts. |
| **Prevent sleep while collecting** | On | Keeps the computer awake while the collector is running, so collection isn't interrupted. The display can still turn off on its own schedule. |

## Sending

| Setting | Default | Range | Description |
|---------|---------|-------|-------------|
| **Flush interval** | 5000 ms | 100–60000 | How often collected data is sent to the server. Requests are automatically sized to stay within the API's limit of 100 readings per request. |
| **Compress outbound requests** | On | — | Gzip-compresses each request before sending, to reduce bandwidth. |
| **Max data points in queue** | 50,000 | 1,000–1,000,000 | Cap on the on-disk send queue that preserves data across lost connections and app restarts. Once it's reached, the oldest entries are dropped to make room for new ones. |

Settings changed from their default show a reset button next to them.

## Outbound Queue

Data collected but not yet sent to the server:

- **Data points waiting**
- **Queued batches**
- **Size on disk**
- **Oldest waiting since** — shown while anything is queued.
- **Retrying** — the number of batches being retried, and the maximum attempts per batch. Shown only while a retry is in progress.

<Warning>
  **Clear Queue** permanently discards all unsent data in the queue. Use it only if you don't need that data forwarded.
</Warning>
