Before it can collect or forward any data, Factory Flow Gateway must be registered to your Factory Flow organization. Registration links the desktop app to a gateway record in the cloud, which is where you'll later assign machines to it.

## Getting a Gateway Token

Registration requires a **gateway token** — a string that starts with `gw_`.

1. Sign in to the Factory Flow web app.
2. Navigate to **Manage → Organization → Gateways**.
3. Create a new gateway (or open an existing one) and copy its token.

<Note>
  See [Gateways](/manage/organization/gateways) for how gateway records are created and managed in the web app.
</Note>

## Registering in the App

<Steps>
  <Step title="Open the registration screen">
    Open **Settings → Server**. Until the gateway is connected, it shows the **Connect to Factory Flow** form. (The **Machines** page also has a **Go to Settings** button that takes you there.)
  </Step>
  <Step title="Choose where your Factory Flow is">
    Leave **Factory Flow Cloud** selected for the standard cloud service. If you're connecting to a self-hosted Factory Flow deployment, choose **Self-hosted** and enter your organization's **Server URL**.

    <Tip>
      If your self-hosted server's certificate was issued by an internal or private CA rather than a publicly trusted one, use the **CA certificate (optional)** field that appears under **Self-hosted** to point the gateway at that CA's certificate so it can verify the connection. This is how gateways trust a server set up with [`./factoryflow cert`](/self-hosted/ssl-and-proxies#private-ca-for-lan-only-deployments) for a LAN-only deployment — run `./factoryflow cert export` on the server, transfer the resulting file to this machine, and select it here. Leave this blank for a self-hosted server with a publicly trusted certificate.
    </Tip>
  </Step>
  <Step title="Enter your gateway token">
    Paste the `gw_` token you copied from the web app.
  </Step>
  <Step title="Connect">
    Click **Connect Gateway**. The app validates your token against the server and, once successful, links itself to that gateway record.
  </Step>
</Steps>

## After Registration

Once registered, **Settings → Server** switches from the setup form to a live status view — connection status, organization, plan, license, assigned machines, connection security, masked token, and gateway details. See [Settings → Server](/gateway/settings/server) for the full field reference.

If the gateway can't connect, the setting responsible is highlighted in red with a short reason: the **Server URL** when the server can't be reached, the **Gateway token** when it's invalid, expired, revoked, or locked to a different device, or the **CA certificate** when its file can't be read or the server's certificate can't be verified.

<Note>
  To point the gateway at a different server, rotate its token, or change its CA certificate, click **Edit** next to that field under **Settings → Server → Connection**.
</Note>
